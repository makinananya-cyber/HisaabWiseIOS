# ADR-0032 — Home: one endpoint, and the figure that caused D1 is a sentence

**Status:** accepted
**Applies:** [ADR-0020](0020-screen-scoped-endpoints.md) (its first real caller),
[ADR-0016](0016-presentation-details.md) (the donut/meter tool split, and the tip rules),
[ADR-0012](0012-accessibility.md) (both visualisations are replaced, not shrunk),
[ADR-0009](0009-content-cache.md) (tips and article bodies)
**Amends:** nothing — it is the first screen to *use* ADR-0020 rather than describe it
**Records a gap:** the "Show me another" pool is fetched on first press — see the last section

## Decision

### `GET /v1/screens/home` replaces `GET /v1/budget` as what Home reads

Home needs a spending split, a savings meter, a tip, a streak, and three article teasers **at once**. Under a
resource-shaped contract that is four responses and a client-side join, and the join is a calculation: defects
D1, D10, D11, and D16 all happened that way.

**The budget engine has not moved.** Invariant 3 keeps 50/30/20, `saved`, and the goal verdict in one place, and
`Endpoint.budget` is still declared for it — what changed is which route *exposes* them to a screen. The payload
is assembled from the engine server-side, and the corpus asserts it: `home-inr.json`'s `saved` is byte-identical
to `budget-inr.json`'s, because a difference between them is the assembly having derived rather than read.

**Read the payload's field names as a list of things the client may not work out.** `shareOfPayLabel`,
`shareLabel`, `percentageLabel`, `dateLabel`, `monthLabel`, `summary`, `verdict`. The figure D1 was — "% of pay",
computed against a hardcoded `salary: 8000` — arrives as a sentence, so there is no salary on this screen to
hardcode and nothing to divide by.

**Two `Double`s, and they are geometry.** `Category.share` and `Savings.position` are fractions a chart turns
into an angle and a pin into a position. `MoneyFormattingAbsenceTests` still bans `Double` from `Models` and now
names these two as the exemptions, so a third has to be argued for in that file.

### The donut is Swift Charts and the meter is not, from the same ADR

`SectorMark` publishes a per-mark accessibility descriptor for every slice, so VoiceOver moves through the ring as
data; a hand-rolled arc is one shape with one label, and giving it descriptors means re-implementing what the
framework already does. The savings meter is a gradient track with a sliding pin and a floating pill — **not a
mark**, and expressing it as one fights the framework for a shape it does not have.

The rule, stated so the next chart does not have to re-argue it: **a mark the framework knows about, drawn by the
framework; a shape the design invented, drawn by hand.**

Selection is `chartAngleSelection`, which reports a position in the *value* domain rather than a slice, so
`HWDonut.slice(at:in:)` accumulates the shares to find which one was tapped. That is hit-testing — no figure the
user reads comes out of it — and it is `static` and pure so the mapping is asserted rather than eyeballed.

**Both are replaced above the accessibility threshold** (ADR-0012), by the same figures as rows, and the
replacement doubles as the chart's `accessibilityRepresentation` — so the list is what VoiceOver reads whether or
not the list is what is drawn.

### The tip is the server's choice; the cycling is the client's

`dayKey` is in the payload and **is not used to choose anything**. It is there so that "the server picked this" is
checkable: two payloads for different days carry different tips, and a scan asserts that nothing in `ViewModels/`
or `Views/` reaches for the clock.

**Show me another** cycles the **cacheable pool** in memory, resetting next launch, which is what ADR-0016
requires. The pool is fetched on the first press rather than with the screen — Home paints from one request, and
49 tips nobody may ask for is not worth a second one at load time. The substitute keeps *this* payload's currency
token, because a pool identical for everybody cannot carry one user's currency.

`{c}` is substituted client-side from the server-supplied token, so ADR-0003's symbol-spacing rule keeps one
owner, and the amounts inside a tip are illustrative and never converted.

### Two deviations from the design, both argued

**The first-run month keeps the screen.** The ticket asked for the empty state "rendered through `StateView`'s
`.empty`", and that is narrowed deliberately: `.empty` replaces the *whole screen* with one sentence, while the
design puts the grey ring and its CTA **inside the spending card** and leaves the savings meter, the tip, the
streak, and the articles where they are. A new account still has a goal to see and a lesson to start. So the empty
*treatment* is reused in the one card that has nothing in it, and `HomeViewModel.isEmpty` returns `false` with the
reason written at it. `StateView`'s own note — "the CTA that belongs on an empty screen is the screen's own, and
arrives with the first screen that has one" — is what this is.

**Editorial emphasis becomes markdown.** The design writes `<b>` and `<i>` inline in tips, article paragraphs,
steps, and list entries. HTML cannot reach a `Text`, so the extraction converts it and `HWMarkdown` renders it
through `AttributedString`. Stripping it was the alternative and it loses the point of the sentence: "no bank will
*ever* ask for your OTP" and "worked out from your **basic salary only**" both put the weight on the word that
changes the meaning. Markdown in a `Text` is free for *app copy* — a `LocalizedStringKey` is parsed as markdown —
and this is server content going through `Text(verbatim:)`, which is not, so the parse is explicit.

### `ContentResource` gained a parameter

An article body is per-article, so the enum stopped being `String`-raw-valued and `CaseIterable`: `case
article(id:)` is part of the cache key, and the id is filtered to letters, digits, and hyphens because it arrives
from a payload and one containing a slash would write outside the store's directory. `ContentResource.fixed`
replaces `allCases` for the four resources that exist without being asked for by id.

`FixtureCorpusTests` learned that a parameterised route's instances start with its collection path, so
`/v1/content/articles/scams` is covered by the declared `/v1/content/articles` — equality would have forced either
a literal per article id or a fixture claiming nothing.

## Three scans narrowed rather than weakened

Each one caught something legitimate, and each now names the exemption so the next one has to be argued:

- **`Double` in `Models`** — the two geometry fractions, by field name.
- **`.minor` in `Views`** — one comparison, `savings.saved.minor == 0`, which chooses between two catalogue
  sentences. Comparing a figure with nothing is not spelling one out, and the alternative was a server field
  meaning "is it zero".
- **The localisation key scan** — it now subtracts `HomeView.symbol(_:)`'s five article glyphs the way it already
  subtracted `AppTab`'s five tab glyphs, by asking the type rather than guessing from the text.

And one caught a real mistake: two accessibility values were assembled with `+` across string literals, which is
the sentence assembly ADR-0011 forbids **and** makes the key unreadable to the scan — so the copy would have gone
missing silently. Both are single literals now, with the arguments pulled out as locals.

## Consequences

- Home is one request. The tip pool is a second, and only on demand — cacheable content is separate by ADR-0020's
  own rule rather than as an exception to it.
- Every card on the screen agrees about `saved` for the structural reason that one response carried all of them.
  The D1 regression test asserts the corpus agrees with the engine's own payload; the screen cannot disagree with
  itself.
- An article body is a `BaseView` over cacheable content — the first time those two meet. The taxonomy is
  unchanged: a body that will not load is `.offline` or `.failed` exactly as a screen payload would be.
- `HomeView` takes its two destinations as closures, because both are *tabs* and the shell owns the selection.

## What looking at it running found

**The category key had vanished at ordinary sizes.** Fixing the duplicate the review found — the key rendered
twice at accessibility sizes, because `hwVisualisation` supplied it *and* the screen drew it — went one step too
far and left it supplied only by the modifier, which draws it only *above* the threshold. So the categories were
invisible at every size a user actually reads them at.

The resolution is the one that was available all along: the key belongs to the **screen**, drawn at every size as
the design draws it, and the ring's replacement is `EmptyView()` — above the threshold the ring simply goes and
the list that was already there remains. One list, either way.

**And one line was removed for claiming something it did not do.** A `chartXScale(domain:)` was added to close the
ring's seam, on the theory that the shares summing to `0.9999` left a notch. It is not the angular domain of a
`SectorMark` and changed nothing. The seam is the design's own `GAP = 3` between segments — the ring is
deliberately not a closed circle — and the last-to-first gap only *reads* wider because it is the one gap with the
same colour on neither side. Recorded at the constant rather than left as a comment that was wrong.

## The four criteria this ticket first missed

Each was found by reading the acceptance criteria against the screen rather than against the code, and each is now
built:

- **The first-run grey ring is drawn**, in the empty-track role, with the readout zeroed — "Total spent · ₹0 ·
  nothing yet" — as `drawEmptyDonut()` draws it. An SF Symbol stood there, which made the first day's card a
  different card from every day after it.
- **The meter's label travels with the pin.** Centred on it, clamped so it stays inside the card at either
  extreme, and its arrow re-aimed at the pin it has stopped being centred on — which is a large part of why the
  meter is hand-built at all, and was missing from the thing that cited it. The saved figure left the foot row,
  where it had been printing the same string twice.
- **The next lesson is named on the control that goes to it**, rather than only inside the server-composed
  summary. `nextLesson` was decoded and rendered nowhere.
- **The `SectorMark` descriptors are reachable.** `hwVisualisation` installed the alternative as the chart's
  `accessibilityRepresentation` unconditionally, which *replaced* them — so they were read by nothing at any size,
  and ADR-0016's stated reason for choosing Swift Charts was unrealised. The modifier now takes
  `describesItself:`, which is `false` for every hand-built shape (a gradient with a pin has no descriptors, so
  the list must stand in) and `true` for a chart that publishes its own.

## The gap this leaves

**The pool is fetched on the first press of Show me another**, so that press can be slow on a bad connection while
every one after it is instant. Prefetching it with the screen would fix the first press and cost every user who
never touches the control a 49-tip download. The better answer is probably to prefetch it *idly* after the screen
has painted, which needs a place for idle work that the app does not have yet — recorded here rather than guessed
at.
