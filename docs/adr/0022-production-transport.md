# ADR-0022 — The production transport: no URL cache, keyed POSTs, and a Debug-only ATS exception

**Status:** accepted
**Refines:** [ADR-0010](0010-configuration-and-auth-links.md) (configuration), [ADR-0009](0009-content-cache.md) (where a URL cache may live), [ADR-0003](0003-money-presentation.md) (`Accept-Language` has an owner)

## Context

ADR-0010 settled *where the base URL comes from*. Building the real transport surfaced four decisions
it did not cover, each of which has a plausible wrong answer that no test would have caught.

1. **The URL cache.** `URLRequest.cachePolicy = .reloadIgnoringLocalCacheData` — which the client has
   set since the walking skeleton — stops a response being **read** from the cache. It does not stop
   one being **written** to it. Invariant 8 says a cache HIT on per-user data is a data breach; a
   salary sitting in `Library/Caches` waiting for a HIT that never comes is the same data in the same
   place.
2. **`Idempotency-Key`.** The backend "accepts `Idempotency-Key` where retries are plausible (expense
   create)". The client has to decide whether that is a property of a path or of a verb.
3. **App Transport Security.** `wrangler dev` serves cleartext HTTP on loopback, so a Debug build
   needs an exception. ATS is not expressible as a build setting, only as an `Info.plist` key — and a
   project with one `Info.plist` ships whatever exception it grants.
4. **`Accept-Language`.** ADR-0003 makes the server format money honouring it, which means the header
   is load-bearing. The type that owns the language choice is `@MainActor`; the client is an `actor`.

## Decision

**The API session carries no URL cache.** `URLSessionTransport`'s configuration sets `urlCache = nil`
as well as the per-request bypass. Cacheable content — tips and articles — gets **its own session**
when it arrives, rather than sharing the one that carries per-user payloads. ADR-0009's content store
is unaffected: it is an explicit on-disk JSON store with persisted ETags and was never `URLCache`.

**Every `POST` carries an `Idempotency-Key`**, generated by the client unless the caller supplies one.
It is a property of the verb, not of a path list: a per-endpoint table is a thing that falls out of
step with the routes, and the failure mode is expense create being the one call that forgot. `PUT` and
`DELETE` carry none — both are idempotent by definition, and a key there would imply otherwise.

**The ATS exception lives in a Debug-only `Info.plist`.** `Configuration/` holds two: `Info.plist` for
Staging and Release, and `Info-Debug.plist`, which is the same file plus a `localhost`-scoped
`NSExceptionAllowsInsecureHTTPLoads`. `NSAllowsArbitraryLoads` appears in neither, and
`BuildConfigurationTests` asserts that the two differ by exactly that one key. `AppConfig` refuses a
cleartext URL for any host but `localhost`, so the code and the plist cannot drift into disagreement.

**`Accept-Language` comes from `LanguageSource`**, a protocol in `Models/` that `LanguageManager`
conforms to, read with `get async` because the owner is main-actor-isolated. **It is not a second
seam** (ADR-0013): nothing conforms to it but the real manager, in the app and in the tests alike, and
`AppEnvironment` builds the client so that the UI's manager and the client's are necessarily the same
object.

## Consequences

- A per-user response never reaches the on-disk URL cache, which makes invariant 8 a property of the
  session rather than a discipline every route has to remember.
- The content-cache ticket inherits a constraint: it gets a session of its own. That is a smaller cost
  than the alternative, which is one session whose caching depends on which route is in flight.
- A caller that wants **one key per user intent** — a "try again" button in front of a write (#18) —
  passes its own key and reuses it. The generated default is one key per call, which is correct while
  ADR-0019 leaves the app with no automatic retries at all.
- Two `Info.plist` files can drift. The test that enumerates their difference is what makes that a
  failure rather than a surprise.
- Debug builds no longer run on fixtures. The app talks to `wrangler dev`, so "it works" now means
  something about the real client; with no Worker running, every screen shows the offline state, which
  is the honest rendering of that situation. Fixtures remain the seam for tests and previews.
- **Rejected:** keeping a `URLCache` and suppressing storage per request with a `URLSessionDataDelegate`
  `willCacheResponse` hook. It works, and it makes the guarantee depend on a delegate callback firing
  for every task — an invariant that fails silently the first time someone adds a request that does not
  go through this transport.
- **Rejected:** a single `Info.plist` with the localhost exception in it, on the grounds that
  `localhost` resolves only to the loopback interface so shipping the exception is harmless. It is
  *nearly* harmless, and it puts an ATS exception in the production binary for a later edit to widen.
